# PulseC 0.1.0-rc.1 本地发布验收

日期：2026-11-09。交付目标是可下载、自托管的 Linux amd64 候选；没有对公网部署或发布镜像。运行代码来自 `e0c6401` M0 之后按功能提交的更改。用[打包脚本](../scripts/package.sh)从指定 Git 提交的干净文件构建，包内 SOURCE_COMMIT 记录该提交，包外 SHA256SUMS 用于校验本地候选。下列高并发、浏览器及长时测试使用同一原生可执行文件：SHA-256 `85291bac10b70af76d983d5b75bb886224e4ec5419b44ca86d2ece4f9113d80c`。

## 并发验收

AMD Ryzen 7 5700G（8 物理核）、Linux 7.2.4、Go 1.26.10，同一台回环主机；中继绑逻辑 CPU 0–3、客户端 4–7。512 个独立 QUIC 连接，24 人/s 入场，全员同步后 128 条原创消息/s、每条正文 128 字节、持续 30 秒。冷启动、每个场景各三轮，轮间交换 M0 与候选先后。P99 包含客户端调度，每轮取得结果后再对各指标取中位数。基准是实际交付的 M0 二进制（`e8177fe3…a8179f`，带历史 PGO）；候选从当前源码树构建。二者差异不能单独归因于应用代码或 PGO。

每轮提交并确认 3,840 条。单频道每轮应投 1,966,080 份、分散频道 61,440 份，均全部收到，重复、串房、限速和中途断开计数均为零。上述均是固定负载测试，不代表吞吐上限。压测与构建共享工作站，尤其第三轮单频道 M0/RC 分别达到 79.74/38.07 ms；三轮中位数不能视为独占机器的固定性能收益。[三轮逐次 JSON](../qa/results/rc1-paired.jsonl)

停止其他构建后的配对复查中，单频道一对的 P99 为 M0 11.29 ms、RC 8.43 ms。32 个频道三对的中位数为 M0 0.68 ms、RC 0.94 ms，RC 稳态峰值 RSS 为 98.1 MiB。分散频道约 0.26 ms 的差距在这台机器上复现，归因仍待单独验证。所有确认和应投份数均齐全。本报告对应上文指定摘要，后续代码调整应以其直接前一版为对照。[复查逐轮数据](../qa/results/rc1-recheck.jsonl)
