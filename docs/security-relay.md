# 首次发布：中继人工审查与复测

范围：单实例 Go 中继、HTTP/3 WebTransport 接入、房间内的授权和匿名限额。以恶意浏览器页面、可直接构造协议消息的客户端、能更换 trip 的单个来源，以及慢客户端为攻击者；中继进程或用户设备失陷不在本次模型内。匿名指无需账户，公网中继仍能看到传输端地址和经手的明文消息，私聊也不是端到端加密。

| 检查项 | M0 的问题或待验证边界 | 候选版措施及证据 |
|---|---|---|
| 容量 / 慢客户端 | 每人有有界发送队列和扫描长度，但大量匿名会话、重复查询或快速更换身份仍可消耗全实例资源 | 升级前限制 QUIC 握手速率、HTTP/3 连接与会话并发、请求头和流；独立限制 TCP。超限不挤出已在线会话。慢接收者队列满后单独关闭，其他成员继续得到 ACK |
| 元数据增长 | 回执靠定时过期，没有容量上限；某些无效发送会留下空 trip 限额项 | 房间、已知频道查询、回执、来源限额表均设上界。新发送无法记下回执时先拒绝，不出现已经广播但无法幂等重试的状态。无效发送不建立 trip 发言记录，最后一个成员离开即删房间 |
| 匿名滥用 | 切换 trip 能绕开单 trip 限制；修改主题会让房间全员更新名单 | 增加短时来源预算（不采信转发头）及频道主题修改冷却；目录/成员操作有单连接预算。不同来源的普通用户仍可发言。大规模分布式攻击、合法大规模共享 NAT 误限和上游带宽耗尽仍需运营处置 |
| 身份及可见性 | 连接级成员编号、未列出频道和定向私聊须在协议演化中保持正确 | 迟入者无回放；私聊同昵称歧义报错而非任选，未入房不能发言，已确认的 ID 重试只返回 ACK。旧版全量名单与增量名单可共存。未列出频道不提供访问授权，不应用房名传递敏感信息 |
| 跨站接入、畸形输入 | 本机开发 TCP 路径有 Host 检查，HTTP/3 没有统一应用；重复 Origin 不能只取第一个值 | 两条监听路径使用同一浏览器响应头及回环 Host 检查；CONNECT 要求唯一且完全匹配的 Origin。真实受信 TLS 上向三个客户端分别送入越界帧、畸形 JSON 和非法 UTF-8；坏会话断开，正常会话仍能 ping |
| 诊断泄漏 | 底层库或默认 HTTP 日志可能包含对端地址或对端提供的错误信息 | 禁止底层默认日志进入业务输出，服务端只记录明确的启动/配置错误或可选的汇总计数，不记录消息、proof、房名或来源地址。使用能重用的合成凭据和含标记的关闭原因作发布实测；宿主机、代理、崩溃转储和浏览器日志仍需部署者单独检查 |

可复现：在前端已构建的仓库运行 `go test -race -count=1 ./...` 和 `go test -fuzz=FuzzUntrustedCommand -fuzztime=30s ./internal/chat`。[协议测试](../internal/chat/hub_test.go)、[资源上界测试](../internal/chat/limits_test.go)、[真实网络坏帧测试](../internal/server/webtransport_test.go)和[协议样例](../testdata/protocol.json)均入库。2026-11-09 的短模糊测试在 4 秒内执行 132,818 次，没有发现崩溃或未授权创建房间/回执；这不能证明不存在漏洞。对公网入站可达性和上游抗流量攻击能力的判断需要实际部署环境，扫描与报告流程见[安全政策](../SECURITY.md)。
